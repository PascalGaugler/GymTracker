# Design audit: consolidated findings

Consolidates the five per-group design-audit passes into one report. Each group
compared the live app (`localhost:5173`, source + live DOM measurement, no
browser screenshots taken by the tokens group) against Claude Design's
prototype (`design-reference/screens.jsx`, `components.jsx`, `charts.jsx`,
`Gym Tracker Prototype.html`, `Design System.html`, `tokens.css`,
`prototype.css`, `tweaks-theme.css`) resolved at the app's **default**
settings: `data-mood="electric"`, `data-surface="slate"`, `data-form="balanced"`.

- Widths checked: **320px** and **390px** for the app (same-origin iframe
  harness), plus a plain desktop tab (~1528–1568px, content capped at
  `max-w-screen-sm`). The prototype was checked at its native **390px** phone
  frame only — its own 320px behaviour is not a design reference, per brief.
- Groups and source files:
  - [`docs/design-audit/tokens.md`](./design-audit/tokens.md) — design tokens
    - shared components (`Button`, `Card`, `Sheet`, `Dialog`, `DropdownMenu`,
      `Tabs`, `Input`, app shell). Source-only, no screenshots.
  - [`docs/design-audit/dashboard.md`](./design-audit/dashboard.md) — app
    shell (header/tab bar) + Dashboard + weight/measurement quick-add sheet.
  - [`docs/design-audit/log.md`](./design-audit/log.md) — `/log` workout
    picker + `/log/:sessionId` active session + per-set weight input.
  - [`docs/design-audit/progress.md`](./design-audit/progress.md) — all 4
    Progress hub tabs + exercise drilldown.
  - [`docs/design-audit/manage-settings.md`](./design-audit/manage-settings.md)
    — Manage (plans/workouts/exercises) + Settings, checked for internal
    consistency (no prototype equivalent exists for these screens).
- Screenshots: `<scratchpad>/screens/{dashboard,log,progress,manage-settings}/`
  (session-scoped scratchpad directories cited by each group file; not
  committed to the repo). The tokens group is source-only, no screenshots.
- No DB writes, imports/exports, or saved sessions were created by any group;
  no cleanup required.

This file does not modify or duplicate the five source files — read them for
full detail on any item; this file is the merged, de-duplicated index.

## Summary

**47 consolidated items** total (16 cross-cutting `X-` items covering 45 of
the 76 original rows, + 31 remaining screen-specific items), covering **all
76 original findings** (`T-01`..`T-10`, `D-01`..`D-22`, `L-01`..`L-15`,
`P-01`..`P-14`, `M-01`..`M-15` — see the coverage table at the bottom).

**By severity:** 19 high · 10 medium · 18 low.

**9 CONFLICT items** (an explicit CLAUDE.md / `docs/design-system.md` /
`docs/charts.md` rule is cited as the tie-breaker): `X-01`, `X-02`, `X-03`,
`X-04`, `X-12`, `L-01`, `P-03`, `P-11`, `M-01`. **0 OUT-OF-SCOPE items** —
none of the five groups found a finding that touches Yazio/calorie sync or
the training-frequency heatmap (the only two documented Phase-2/3 deferrals);
see Section D.

**Top 8 most visible issues:**

1. Almost every button/icon-button in the app is under the CLAUDE.md 48px tap
   target minimum — `button.tsx`'s size scale has no 48px step (`X-01`).
2. A native `<select>` in the workout-slot editor blows out to 505px inside a
   358px-wide dialog and can make the dialog's own Save button unreachable
   (`M-01`).
3. The active-session weight input silently drops digits at 320px — a saved
   `71.5` renders as `71.` (`L-01`).
4. `cn()`/`tailwind-merge` silently drops the custom `text-caption` utility
   whenever it's combined with a color class, collapsing tabs/chips to the
   16px browser default instead of 13px (`X-15`).
5. Dashboard stat-card labels are fully hidden at 320px and mid-word
   truncated at 390px because the label/badge row doesn't wrap (`X-12`).
6. The shared `Sheet` and `Dialog` primitives were never restyled for this
   app's tokens (wrong background, no elevation shadow, no grab handle, wrong
   radius, under-dimmed scrim) — affects every sheet and every Manage dialog
   (`X-02`, `X-03`).
7. Every Progress tab is missing the prototype's "insight" box — the
   plain-language Trend-badge takeaway the app's core thesis rests on (`P-05`).
8. Screen-header "overline" labels are hard-coded primary blue app-wide
   instead of the prototype's quiet grey default (`X-05`).
