# Design audit: Progress hub

Screens/states covered: `/progress/recomposition` (default), `/progress/strength`
(workout selector + per-exercise toggle chips + swap hint), `/progress/exercise/:id`
(exercise picker + top-set/min–max band drilldown), `/progress/body` (bodyweight
rate card + raw/7-day-MA trend chart + waist/chest/biceps comparison chart).
Prototype equivalents: all 5 `PROG_TABS` (Recomp/Workout/Übung/Gewicht/Körper) in
`design-reference/screens.jsx` `Progress()`, plus `design-reference/charts.jsx`
(`LineChart`, `Sparkline`, `markerShape`) and the Dashboard's `.recomp-mini`
preview (chart styling only — D-03 in `dashboard.md` already covers the missing
card itself, not repeated here). Chart/shell/header basics already audited in
`tokens.md` (T-03 Card primitive, T-05 type-scale abstraction, T-07 segmented
control, T-09 TrendBadge) and `dashboard.md`/`log.md` — referenced, not repeated.

Widths checked: 320px and 390px (app, same-origin iframe harness at
`localhost:5173`), plus a plain desktop tab (~1568px, content capped at
`max-w-screen-sm`). Prototype checked at its native 390px phone frame only (its
320px behaviour is not a design reference, per brief).

Screenshots: `<scratchpad>/screens/progress/`

## Confirmed correct (no finding)

- **No dual y-axes anywhere**: `RecompositionChart.tsx` and `MeasurementComparisonChart.tsx` each render exactly one `<YAxis>` with both/all series sharing it — matches CLAUDE.md and docs/charts.md's "never use dual y-axes" rule.
- **Fixed baseline, never rolling**: `recomposition.ts:96-98` (`BASELINE_SESSION_COUNT = 3`, median of the first N sessions) — matches docs/charts.md exactly, including the outlier-robust median choice.
- **Top set, not average**: `topSetsPerSession` (`recomposition.ts:56-67`) takes the max weight per exercise per session, reused by both the strength index and the per-workout progression — matches docs/charts.md.
- **Swap-aware rendering**: `strengthProgression.ts` rows carry `null` for un-logged exercises and `StrengthProgressionChart.tsx` renders with `connectNulls` **off** (the default) — a swapped exercise never bridges to its replacement, matching docs/charts.md exactly. (`RecompositionChart`/`MeasurementComparisonChart` correctly do the _opposite_ — `connectNulls` **on** — to bridge two independently-timestamped series onto one shared axis, also per the Phase 6 "Learnings" distinction.)
- **Axis tick / grid styling matches the prototype almost exactly**: `axisTick` (`fill: var(--subtle)`, `10px`, `var(--font-mono)`) in every chart component matches `charts.jsx:74,86` (`fontSize="10" fontFamily="var(--font-mono)" fill="var(--subtle)"`) value-for-value; `CartesianGrid stroke="var(--grid)"` matches `charts.jsx:73`'s gridline colour.
- **Baseline `ReferenceLine` styling matches closely**: dash `"2 4"`, `var(--border-strong)`, `9px` mono label in `var(--subtle)` — matches `charts.jsx:80-82`'s baseline treatment in both `RecompositionChart.tsx:103-114` and `MeasurementComparisonChart.tsx:99-110`.
- **Body chart is already docs/charts.md-compliant and _better_ than the prototype's own "Gewicht" tab** — see P-11.

## Likely shared root causes

1. **`cn()`/`tailwind-merge` drops custom font-size utilities when merged with a color class** (P-02) — the single highest-impact, least-obvious finding in this group: `text-caption` (and likely other custom `--text-*` scale classes) silently collapses to the 16px browser default wherever a `cn()` call combines it with any `text-{color}` class. Confirmed on 3+ components; almost certainly present outside Progress too, since `cn()` is the app-wide className utility.
2. **Prototype's per-series marker glyphs (circle/square/triangle/diamond/cross/star) were not carried over** (P-04) — every chart, legend swatch, and tooltip in the app uses a uniform circular dot, losing a shape-based redundant cue the prototype relies on consistently.
3. **The prototype's `.insight` box (Trend badge + plain-language takeaway) was never built as a shared pattern** (P-05) — missing from all three Progress views that have a prototype equivalent for it (Recomp, Strength, Body); the `TrendBadge` primitive it needs already exists elsewhere in the codebase.
4. **Summary/delta stat-tile rows above a chart (`.ex-stats`) were not carried over for the exercise drilldown or measurement comparison** (P-06, P-07) — only the bodyweight chart got an equivalent (`StatCard`-based `RateCard`, a deliberate Phase 8 substitution); the exercise and measurement views have no substitute at all.
5. Cross-references to other groups' root causes that also surface here, not re-diagnosed: **T-03** (shared `Card` primitive — every `chart-card`-equivalent wrapper in this group is a plain shadcn `Card`), **T-07** (segmented-control low-contrast active state — P-01 is its concrete instantiation on both Progress switchers), **T-05** (deliberate type-scale abstraction — explains ~2-6px deltas, does _not_ explain P-02's 16px-vs-13px gap, which is a bug not a scale choice), **L-10** (`--muted-foreground` used where `--subtle` is intended — P-08's colour half).

## Blocking / out of scope

Nothing blocking. **2 CONFLICT** rows (P-03: stepped-vs-monotone lines vs. docs/charts.md's stair-step expectation; P-11: the _prototype's_ own raw-only "Gewicht" tab violates docs/charts.md's raw+7-day-MA rule — the app is already compliant there, no fix needed). **0 OUT-OF-SCOPE** rows — none of the prototype's 5 Progress tabs reference calories/Yazio or the training heatmap (those only appear on the Dashboard, already covered by `dashboard.md` D-22).
