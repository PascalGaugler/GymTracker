# Design audit: Tokens & shared components

Screens/states covered: none directly (this is the foundations group — design
tokens plus the shared/reusable pieces: `Button`, `Card`, `Sheet`, `Dialog`,
`DropdownMenu`, `Tabs`, `Input`, and the app shell `AppLayout`/`BottomTabBar`/
`PageHeader`/`TrendBadge`). Per-screen usage is covered by other audit groups;
rows below note which screens each shared piece affects.

Screenshots: none — this is a source-only audit (no browser used, per task
instructions; another agent owns the live-app/prototype screenshots).

Method: resolved `design-reference/tokens.css` + `tweaks-theme.css` (no
override, i.e. defaults `data-mood="electric"`, `data-surface="slate"`,
`data-form="balanced"`) + the base rules in `prototype.css`, read side-by-side
with `src/index.css`, `docs/design-system.md`, `design-reference/components.jsx`,
`design-reference/Design System.html`, and the shared component source files.

## Confirmed correct (no finding)

Resolved for the defaults (mood=electric, surface=slate, form=balanced), essentially every color, radius, elevation, spacing, and chart-palette value in `src/index.css` matches `design-reference/tokens.css` **exactly, hex-for-hex** (not oklch — this app defines shadcn's semantic vars as plain hex, sidestepping the oklch-vs-hex comparison problem the audit brief anticipated): surfaces (`--background #0a0c12`, `--surface/--card #11141d`, `--surface-2/--muted #181c28`, `--surface-3 #20253480`, `--popover #141823`, `--sheet #12161f`), foreground levels, borders, primary/accent (+hover/pressed/soft/foreground), semantic success/warning/danger (+soft), the 6-color chart palette (`--chart-1..6` = `--c1..6`), the recomp pair, radii (6/10/14/20/9999), elevation (`elev-1/2/3`, `inset-hi`), motion durations/easing, and `--tap: 48px`. The type-scale pixel sizes also match `tokens.css` 1:1 (48/36/28/22/18/17/15/14/13/11).

## Likely shared root causes

1. **No 48px step in the shared `Button` size scale** (`button.tsx`) — explains most tap-target violations found across the whole app (T-01); every consumer has to remember to patch it, and several patch it to 44px instead of 48px.
2. **`SheetContent` ships unstyled for the bottom-sheet case** (no radius, wrong background token, no grab handle) — explains inconsistent sheet chrome wherever `Sheet` is used (T-02); the `--sheet` token exists but is dead code.
3. **Generic shadcn `Card` (`rounded-xl` + `ring` + no shadow) used as the base for custom "hero" surfaces** — explains why stat/analysis cards read flatter and rounder than the prototype's cards everywhere they're used (T-03).
4. **The type-scale is a deliberate 10-step abstraction of the prototype's many bespoke per-component sizes** — explains small (~2-6px) size deltas other audit groups will find on headings/values; not a bug, don't re-diagnose per screen (T-05).

Nothing blocking. No OUT-OF-SCOPE items were found in this group (no Yazio/calorie or heatmap-dependent tokens or components surfaced). No CONFLICT item required guessing at intent — all three trace to an explicit CLAUDE.md/`docs/design-system.md` rule.
