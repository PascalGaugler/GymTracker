# Design audit: Dashboard

Screens/states covered: app shell (header + bottom tab bar) as seen from the dashboard;
Dashboard screen (stat-card grid, recomposition preview, "today's workout" card, quick
action); weight/measurement quick-add sheet (opened in both prototype and app, not saved);
empty/first-run state (source-only, not rendered — see note at bottom).

Widths checked: 320px and 390px (app, via same-origin iframe harness at `localhost:5173`),
plain desktop tab (~1528px wide, content still capped at `max-w-screen-sm`). Prototype
checked at its native 390px phone frame only (per brief, its 320px behaviour is not a
design reference).

## Likely shared root causes

1. **`.sc-top`-style row uses `truncate` + `shrink-0` instead of `flex-wrap`** (D-01, D-02) — the single highest-impact fix: switching the stat-card header row to wrap (or stacking label above badge) would resolve both the 320px total-hidden-label and the 390px mid-word-truncation cases in one change.
2. **`src/components/ui/sheet.tsx` was never adapted to this app's sheet tokens** (D-11, D-12, D-13, D-14, D-15) — still shadcn's stock overlay opacity, `bg-popover`, default shadow, no grab handle, and an off-token radius. One pass over this shared primitive fixes five rows at once, for every sheet in the app (not just measurements).
3. **Sub-48px interactive controls recur outside logging** (D-16, D-17) — `size="icon-sm"` (28px) and `size="icon-lg"` (36px) in `button.tsx` are both below `--tap`; anywhere these variants are reused for a real tap target (not just decorative icons) will repeat this conflict.
4. **A "primary-tinted overline" pattern was generalized from one intentional prototype exception** (D-19) — worth checking other screens for the same `text-primary` overline default.
5. **Shared `Card` primitive doesn't route through the token names design-system.md defines for this exact surface** (D-20) — `rounded-xl`/`ring-foreground/10`/no elevation vs. the intended `radius-lg`/`border-border`/`shadow-inset-hi` for resting cards.
